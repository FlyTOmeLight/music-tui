# 歌手详情页、搜索喜欢标记与底部播放控件规格

状态：`ready-for-agent`；功能尚未实施。测试方式已确认。QQ 热门／最新排序能力待验证。

## Problem Statement

用户从歌曲看到歌手名后，无法直接进入该歌手的歌曲列表，也无法按热门或最新顺序继续找歌。搜索结果没有喜欢状态，用户需要另外查询才能知道是否已收藏。主界面底部显示当前歌曲和播放信息，但缺少可点击的切歌与暂停控件。

## Solution

为 QQ 音乐与网易云 Enhanced 增加歌手详情页，展示头像、姓名、简短简介和分页歌曲列表。每位歌手的名字可独立点击，键盘操作也能选择目标歌手。歌手歌曲按热门或最新对完整列表排序，再分页展示；从列表选歌后，顺序播放沿该顺序跨页继续。

搜索结果增加可点击的喜欢标记，与现有 `S` 键操作保持一致。主界面底部增加上一首、暂停／继续、下一首按钮，复用现有播放队列和播放动作。

## User Stories

1. 作为 QQ 音乐用户，我希望进入歌曲对应的歌手详情页，以便继续寻找这位歌手的歌曲。
2. 作为网易云 Enhanced 用户，我希望使用相同的歌手浏览方式，以便切换平台后仍能完成相同操作。
3. 作为鼠标用户，我希望点击歌曲列表中的歌手名进入详情页，以便直接查看歌手作品。
4. 作为正在听歌的用户，我希望点击底部当前歌曲区域或独立播放页的歌手名，以便从正在听的歌曲继续探索。
5. 作为合唱歌曲的听众，我希望分别点击每位歌手的名字，以便进入自己选择的歌手页。
6. 作为键盘用户，我希望能从当前歌曲选择目标歌手，以便不依赖鼠标浏览合唱歌手。
7. 作为浏览歌手的用户，我希望看到头像、姓名和简短简介，以便确认歌手身份。
8. 作为浏览歌手的用户，我希望在头像或简介缺失时仍能浏览歌曲，以便继续找歌。
9. 作为找代表作的用户，我希望按热门顺序浏览歌手歌曲，以便先看到热门作品。
10. 作为找新歌的用户，我希望按最新顺序浏览歌手歌曲，以便先看到近期作品。
11. 作为翻页用户，我希望热门／最新顺序覆盖全部歌曲，以便下一页仍接续所选顺序。
12. 作为切换排序的用户，我希望回到新顺序的第一页，以便从该顺序的起点开始浏览。
13. 作为浏览歌手的用户，我希望加载、空列表和请求失败有明确提示，以便知道当前状态并在失败后重试。
14. 作为顺序播放用户，我希望从歌手页选歌后继续播放该顺序的后续歌曲，以便无需每页重新选歌。
15. 作为跨页听歌的用户，我希望当前页结束后能播放下一页的歌曲，以便连续听完歌手列表。
16. 作为正在听歌的用户，我希望浏览歌手页或切换排序时保留当前播放队列，以便探索歌曲时音乐继续播放。
17. 作为返回列表的用户，我希望返回后保留原列表、页码和选中歌曲，以便接着刚才的位置浏览。
18. 作为使用播放来源的用户，我希望能从正在播放的歌手歌曲返回对应歌手及排序位置，以便定位当前歌曲。
19. 作为使用手动待播、最近播放和播放会话的用户，我希望歌手歌曲保留其播放来源，以便这些现有功能仍能定位或恢复相应歌曲。
20. 作为搜索用户，我希望看到已喜欢、未喜欢或未知状态，以便知道当前账号是否喜欢每首歌曲。
21. 作为鼠标用户，我希望点击喜欢标记即可喜欢或取消喜欢，以便在搜索结果中直接操作。
22. 作为键盘用户，我希望继续用 `S` 键修改喜欢状态，以便沿用已有操作习惯。
23. 作为修改喜欢状态的用户，我希望成功后立即看到新状态，失败时保留已确认的状态并得到错误提示，以便知道操作是否完成。
24. 作为未登录或遇到查询失败的用户，我希望看到未知标记，以便不会把未知误认为未喜欢。
25. 作为切换账号或平台的用户，我希望喜欢标记属于当前账号，以便不会看到其他账号的状态。
26. 作为鼠标用户，我希望在主界面底部点击上一首、暂停／继续和下一首，以便完成常用播放操作。
27. 作为键盘用户，我希望现有播放快捷键继续可用，以便按钮加入后不改变操作习惯。
28. 作为 80×24 终端用户，我希望新增控件可见且可操作，以便在常见终端尺寸下使用全部功能。

## Implementation Decisions

### 歌手身份与平台边界

- 共享歌曲值保留平台返回的歌手身份列表，同时保留现有歌手展示名称。每位歌手具有所属平台可识别的 ID 和姓名；详情页使用身份查询，不用同名文本搜索代替指定歌手。
- 音乐访问模块提供歌手详情与歌曲分页操作。详情包含姓名及可选头像、简介；歌曲分页包含歌曲、后续页信息和接口可提供的总数。
- 歌手歌曲查询显式接收热门／最新顺序，由平台适配层转换为真实接口参数。全列表排序在分页前完成，不以当前页排序替代。
- QQ 已安装 SDK 提供歌手详情和分页歌曲接口，但歌曲排序参数固定，尚未核实热门／最新参数。该能力保持待验证，不能写成已支持，也不能静默降为本页排序。若无法满足，需重新确认 QQ 的排序方案。
- 网易云 Enhanced 本机接口模块接受热门／时间排序和分页参数；实现时仍需核实响应顺序与翻页行为。
- 网易云官方模式已被用户确认废弃，不纳入本规格；仓库仍存在的官方实现与说明不改变本次范围。

### 歌手页与交互

- 默认显示热门；切换热门／最新后，从第一页加载新顺序。
- 歌手页包含头像、姓名、简短简介与歌曲列表，本次不加入专辑列表或专辑入口。
- 歌曲列表、底部当前歌曲区域及独立播放页均提供歌手入口；合唱歌曲的歌手名分别可点击，键盘操作提供歌手选择框。具体快捷键沿用项目约定，在实现时确定，不覆盖现有快捷键。
- 歌手页复用现有歌曲列表的选歌、翻页和播放行为，但热门／最新是独立的全列表顺序，不能沿用现有“本页排序”作为实现。
- 返回恢复进入前的页面与浏览状态，包括列表、页码、选中歌曲和焦点；进入详情、返回、点击歌手名或点击喜欢标记本身不选歌播放。
- 加载、空列表和失败可辨识；失败可以重试。更换歌手或排序后，较早请求的结果不能覆盖新选择。

### 播放队列与播放来源

- 用户从歌手页选歌时，建立包含歌手身份、所选排序、页码与歌曲位置的播放来源；顺序播放按该顺序跨页继续。
- 当前播放队列保留建立时的来源及排序。仅浏览其他页面或切换歌手排序不会重建队列；下一次选歌才建立新队列。
- 播放队列继续拥有上一首／下一首、随机历史、单曲循环和手动待播行为。手动待播结束后回到歌手原列表的相应位置。
- 歌手播放来源贯通返回定位、最近播放和播放会话；恢复后保留原歌手、排序及歌曲位置。复用现有账号隔离与主动恢复规则，不引入新的自动恢复方式。
- 最近播放中直接播放历史歌曲仍沿用现有单曲播放行为，保存的歌手来源用于定位；分页导航失败保留原队列与位置，可重试同一导航。
- 不把歌手全部歌曲一次性加载作为全局排序的默认方案；跨页播放通过同一排序的分页接口继续获取歌曲。

### 喜欢状态

- 搜索结果用 `♥` 表示已喜欢、`♡` 表示未喜欢、`?` 表示尚未确认。未登录、正在加载或查询失败都不能当作未喜欢。
- 喜欢状态属于当前平台的已验证账号。复用两平台的完整喜欢列表查询，取得歌曲 ID 集合后为结果打标；避免为搜索结果每首歌曲重复获取完整喜欢列表。
- 账号或平台切换后清除对应界面的旧状态；旧请求结果不能覆盖新账号的数据。现有刷新操作应重新查询喜欢状态。
- 点击标记与 `S` 键使用同一修改动作。排序或翻页后操作的对象仍是点击或选中的实际歌曲，不以旧行号定位。
- 写入成功后更新确认状态及当前可见结果中该歌曲的标记；失败时保留上次确认状态并显示错误。请求进行中避免对同一歌曲重复提交相互冲突的切换。
- 未登录时提示先登录；状态未知时先完成状态查询，再决定喜欢或取消喜欢，不按未知值直接切换。
- 本次只要求搜索结果展示喜欢标记，不将其他列表扩展列为验收要求。

### 底部播放控件

- 主界面底部提供上一首、暂停／继续、下一首按钮，复用现有播放动作，不新增一套队列导航逻辑。
- 暂停按钮根据实际播放状态显示暂停或继续；控件可用性遵循现有播放器状态，无可操作歌曲或播放器未就绪时不发出无效动作。
- 保留空格、`P`、`N` 等现有快捷键。按钮、喜欢标记和歌手入口的点击不会误触整行歌曲播放。
- 常见 80×24 终端下三个按钮可见、可点击、可用键盘操作；结合项目现有的小终端布局检查更窄尺寸，避免遮挡必要的歌曲与播放信息。

## Testing Decisions

用户已确认以下测试方式。测试观察操作结果、显示状态和播放顺序，不约束内部私有函数调用次数或具体界面组件拆分。

- 优先复用最高层的 `MusicApp.run_test()` 与现有假音乐源、假播放器，通过 Textual pilot 操作点击和键盘。沿用现有导航、列表排序、歌单操作、播放队列、平台切换及播放会话测试的准备方式。
- 平台模块补充基于假 SDK 响应或 HTTP 模拟传输的契约测试，覆盖歌手身份转换、详情缺失字段、热门／最新参数、分页边界、喜欢 ID 集合及修改失败。
- 歌手入口：单歌手与合唱歌曲分别进入正确身份；键盘可选择歌手；点击入口不会播放该行；返回恢复列表、页码和选择。
- 歌手列表：两种排序覆盖至少两页，切换排序回到第一页；空列表、请求失败、重试及迟到响应均有可观察结果。
- 播放队列：从热门／最新列表中间选歌，下一首跨页保持原排序；仅浏览或切换排序不改变当前队列；手动待播播放后回到原列表；分页失败可重试且不丢失队列位置；返回定位、最近播放和主动会话恢复保留歌手来源，历史单曲播放行为保持不变。
- 喜欢状态：两平台已喜欢、未喜欢与未知三种显示正确；点击和 `S` 键写入同一歌曲；排序后不操作错误歌曲；成功同步、失败保留、重复点击、刷新、账号切换及迟到请求的结果均符合上述行为。
- 底部控件：点击与快捷键产生相同播放结果；暂停／继续标签跟随播放器状态；未就绪或无歌曲时不触发无效动作。
- 真实接口验证：QQ 的排序参数、返回顺序和跨页行为是该平台排序功能的实施门槛；网易云 Enhanced 需核实歌手详情及热门／最新分页响应。真实接口结果与离线模拟分别记录，不能用模拟测试证明上游能力。
- 布局验证：提供 80×24 终端截图，检查控件可见性、点击区域与键盘焦点，并复用现有小终端检查方式验证更窄布局。
- 实现后完成项目要求的格式、lint、完整测试、构建与安装验证。功能发布按项目规则发布新版本并更新本机全局安装；本次仅生成规格，不进行代码实现或版本发布。

## Out of Scope

- 网易云官方模式的实现、修复、能力补齐及删除旧代码。
- 专辑列表、专辑详情、关注歌手或其他歌手社交功能。
- 在搜索结果以外的所有列表推广喜欢标记。
- 对现有搜索、歌单列表的本页排序进行全局排序改造。
- 新增播放模式、重做播放队列、变更登录方式或自动恢复播放。
- 为缺少歌手身份的历史数据按名字搜索并猜测匹配歌手，或预先添加兼容迁移层。

## Further Notes

- QQ 热门／最新排序能力保持“待验证”。可以先安排接口核实任务，不能把规格发布或 `ready-for-agent` 标签理解为该接口已经可用。
- 用户确认的需求包括两平台范围、歌手页内容、独立歌手点击、全局热门／最新排序、跨页顺序播放、可点击喜欢标记和底部三个播放按钮。
- 默认热门、三个界面的歌手入口及返回保持浏览状态来自需求文档的设计默认值；本规格在此基础上明确了失败、迟到响应与已有播放来源行为，不增加新功能模块。
- 已确认的需求作为本规格的验收依据；QQ 若无法满足排序要求，再讨论具体替代方案，不提前编造回退。
